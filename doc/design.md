# 设计说明

## 目标

`aho4cj` 提供可复用的多模式字节搜索自动机，移植 Rust 上游的高层搜索语义与主要存储策略。实现仅依赖仓颉标准库，
不通过 FFI 包装 Rust 制品。

## 数据结构

构建阶段的 Trie 节点包含三类数据：

- 256 项字节转移表，值为下一节点编号；不存在的转移使用 `-1`。
- 一条失败指针，在当前字节无法继续匹配时回退到最长可用后缀。
- 一个输出列表，记录在当前状态结束的模式编号，并继承失败状态的输出。

模式和输入统一转换为 UTF-8 字节数组。因此 `Match.start` 与 `Match.end` 是半开区间的字节偏移，和上游 Rust
库的偏移定义一致。ASCII 忽略大小写只折叠 `A-Z`，不会更改非 ASCII 字节。

## 构建过程

1. 把所有模式插入 Trie，节点末尾记录模式编号。
2. 从根节点开始广度优先遍历。
3. 为每条边计算失败指针，并合并失败状态的输出。
4. 根据配置冻结为非连续 NFA、连续 NFA 或 DFA，构建期节点不进入搜索热路径。
5. 额外冻结 Trie 直接边，为锚定低层状态转移提供不会经过失败指针的路径。

非连续 NFA 为每个状态保存一张稠密转移表；连续 NFA 将根和浅层状态保存为连续稠密表，深层状态使用连续稀疏边；
DFA 在构建期补全失败转移，使搜索时每个字节只查询一次状态表。字节类把模式中从未出现的字节合并为同一类，减少连续表体积。

自动机构建时间与模式总字节数及所选存储类型相关。扫描复杂度为 `O(n + m)`，其中 `n` 为输入长度、`m` 为结果数。
公开迭代器不预先收集并排序全部候选。

## 匹配选择

- `Standard`：扫描到最早结束位置后立即返回；同一结束位置选择最早起点和最小模式编号。
- `LeftmostFirst`：保存当前最左候选，并最多前看最长模式长度，按模式编号决胜。
- `LeftmostLongest`：保存当前最左候选，并最多前看最长模式长度，按长度和模式编号决胜。
- 重叠搜索：按结束位置、起点和模式编号输出全部候选。

零长度匹配后，搜索游标至少前进一个字节；输入末尾最多报告一次零长度匹配，避免无限循环。

## 预过滤与性能边界

根状态下可用最多三个模式首字节跳过不可能的输入位置。单候选路径按 8 字节展开，双候选和三候选路径也避免通用内层
循环。该预过滤完全使用仓颉代码。Rust 上游会在 `memchr`、稀有字节、Teddy packed 等预过滤器之间启发式选择，并调用
平台 SIMD；仓颉标准库目前没有等价的公开字节搜索原语，因此稀疏搜索仍存在运行时层面的差距。

公开的 `PackedSearcher` 移植了上游 packed API 的左最选择与构建限制，但当前采用独立标量扫描，尚未作为高层自动机的
预过滤器，也不宣称实现 Teddy SIMD。

## 流式处理

流式搜索保存自动机状态和绝对字节偏移，固定缓冲区读取不会破坏跨边界匹配。流式替换额外保留当前活动前缀，只有确定
不再属于未来匹配的字节才写入输出，因此内存使用受缓冲区和最长模式长度约束。

## 线程与可变性

自动机在构造完成后，公开搜索方法只读取冻结后的状态表和自有模式副本。字符串和字节模式都会在构建时复制，因此调用方
后续修改原数组不会影响自动机。

`AhoCorasick` 构建后只读，可在调用方同步策略下复用。`Input`、迭代器和 `OverlappingState` 保存单次搜索进度，不应在
多个并发搜索间共享。
